# Wany — Source Integration Lessons & Guardrails

هذا الملف يوثق الأخطاء والمشاكل التي ظهرت أثناء ضبط مصدر 3asq لصفحة **جديد**، حتى لا تتكرر مع المصادر التالية.

## الهدف الثابت

صفحة **جديد** تعني فقط:
- فصل منشور فعليًا خلال آخر 24 ساعة.
- موجود في المصدر وقابل للفتح.
- له `publishedAt` موثوق من المصدر نفسه.
- لا نستخدم وقت اكتشاف Wany كبديل عن وقت النشر.
- لا نعرض تاريخًا تقديريًا أو مخترعًا.

## ما حصل في 3asq وما تعلمناه

### 1) لا نمسح كتالوج الموقع كاملًا إذا كان المصدر يملك Latest/Recent
الخطأ:
- فحص عدة صفحات من كتالوج الأعمال.
- ثم فتح كل عمل للحصول على الفصول.
- هذا سبب بطء كبير.

الحل:
- استخدم صفحة/قسم المصدر المخصص لـ **أحدث الفصول / Latest / Recent / Updates**.
- parser مستقل لهذا المسار.
- لا تستخدم `getSeries()` لكل نتيجة داخل صفحة جديد إلا عند الضرورة القصوى.

### 2) لا تغيّر أكثر من متغير واحد أثناء إصلاح bug
الخطأ:
- تغيير مسار الجلب وطريقة تقسيم HTML في نفس الوقت.
- النتيجة: اختفت النتائج بالكامل وصعب معرفة السبب.

القاعدة:
- عند وجود مسار يعمل، ثبّته.
- أصلح فقط الجزء المعيب.
- كل commit يجب أن يعالج سببًا واحدًا واضحًا قدر الإمكان.

### 3) عنوان العمل والغلاف يجب أن يؤخذا من بطاقة العمل
الخطأ:
- استخدام أقرب `<li>` للفصل لاستخراج metadata.
- نتج عنه عناوين خاطئة مثل:
  - `AddText_06-16-01.19.28`
  - `بدون اسم203`

الحل:
- title + cover من container العمل نفسه، مثل `page-item-detail` أو ما يقابله في المصدر.
- chapter number + chapter URL + chapter date من صف الفصل نفسه.

### 4) تاريخ الفصل يجب أن يكون scoped للفصل نفسه
الخطأ:
- parsing للتاريخ من بطاقة العمل كاملة.
- الفصل الأقدم ورث تاريخ الفصل الأحدث.
- النتيجة: فصل قديم ظهر كأنه جديد.

الحل:
- كل فصل يجب أن يقرأ تاريخه من row/container الخاص به فقط.
- ممنوع مشاركة timestamp بين فصول نفس العمل.

### 5) لا تستخدم firstSeenAt/discoveredAt كوقت نشر
الخطأ القديم:
- fallback إلى وقت اكتشاف Wany عند غياب `publishedAt`.
- أدى إلى ظهور فصول قديمة كأنها نزلت الآن.

الحل:
- `publishedAt == null` => لا يدخل strict New feed.
- discovery time يبقى للمتابعة الداخلية فقط.

### 6) عند وجود نفس الفصل في أكثر من مصدر
القاعدة:
- dedupe حسب العمل + هوية الفصل.
- استخدم أقدم `publishedAt` موثوق بين النسخ.
- لا تسمح لمصدر mirror متأخر أن يجعل فصلًا قديمًا يبدو جديدًا.
- route القراءة يفضل النسخة التي تحمل الـ timestamp الموثوق المطابق للوقت canonical.

### 7) لا نثق في النصوص الخام من HTML
أضف guardrails:
- رفض عناوين واجهة/placeholder مثل `AddText_...`.
- رفض `بدون اسم...`.
- رفض عنوان يبدو كأنه chapter label فقط.
- رفض item إذا:
  - لا يوجد slug/key صالح.
  - لا يوجد chapter number صالح.
  - لا يوجد `publishedAt` صالح.
  - لا يوجد chapter URL صالح.

الفلسفة:
- **fail closed** في صفحة جديد.
- الأفضل إخفاء نتيجة مشكوك فيها على عرض خبر إصدار خاطئ.

### 8) لا تربط الاختبارات مباشرة بمسار Production Build بدون التأكد من البيئة
الخطأ:
- وضع `npm test` داخل `npm run build`.
- Cloudflare deployment فشل رغم أن الموقع قابل للبناء.

الحل:
- Production build يبقى مستقلًا:
  - `tsc -b && vite build && node scripts/build-sw.mjs`
- الاختبارات تبقى منفصلة.
- إذا أردنا CI gate لاحقًا، ننفذه كـ workflow/job مستقل وليس داخل build command الخاص بـ Cloudflare.

### 9) لا تقلل السرعة على حساب الموثوقية
الأفضل:
- Latest endpoint/parser واحد سريع.
- بدون hydrate لكل عمل.
- لكن لا تُعرض النتيجة إلا إذا تحقق:
  - عنوان العمل.
  - الغلاف إن توفر.
  - رقم الفصل.
  - رابط الفصل.
  - تاريخ النشر الموثوق.

### 10) قاعدة الاختبار لكل مصدر جديد
قبل اعتماده في VERIFIED_NEW_FEED_SOURCES، يجب أن توجد اختبارات تغطي على الأقل:
1. فصل حديث + فصل قديم داخل نفس العمل، ولا يختلط التاريخ بينهما.
2. عنوان العمل لا يتأثر بنصوص UI داخل chapter row.
3. cover مأخوذ من بطاقة العمل الصحيحة.
4. relative date يعمل.
5. absolute date يعمل.
6. unknown date => excluded.
7. duplicate chapter => deduped.
8. malformed result => rejected.
9. latest parser لا يحتاج فتح صفحة كل عمل.
10. opening route يعتمد sourceKey/chapter الصحيح.

## Checklist للمصدر القادم

قبل تفعيل أي مصدر في New:
- [ ] حدد قسم Latest/Recent الحقيقي في المصدر.
- [ ] وثق URL أو API الذي يعتمد عليه.
- [ ] افصل parser الخاص بالـ latest عن parser الخاص بصفحة العمل.
- [ ] title/cover من work container.
- [ ] chapter/date/url من chapter container.
- [ ] لا fallback إلى discovery time.
- [ ] parse التواريخ الخاصة بالمصدر فقط.
- [ ] اختبر relative + absolute + unknown.
- [ ] اختبر وجود أكثر من فصل داخل نفس العمل.
- [ ] اختبر junk UI text.
- [ ] اختبر سرعة path وعدم وجود N+1 getSeries.
- [ ] أضف المصدر إلى VERIFIED_NEW_FEED_SOURCES فقط بعد نجاح الاختبارات.

## مبدأ العمل من الآن

كل مصدر جديد يمر بثلاث مراحل:
1. **Discover**: نحدد Latest الحقيقي وكيف يعرض التاريخ.
2. **Parse**: نكتب parser ضيق ومخصص لذلك المصدر فقط.
3. **Verify**: اختبارات regression + fail-closed guards قبل التفعيل في صفحة جديد.

لا نكرر الحلول العامة بالقوة بين المصادر؛ كل مصدر له HTML/API وطريقة تاريخ مختلفة.
